## 1. Understand the overall structure

Our current program has five main stages:

1\. Initialize the game

Configure graphics and start the SuperTuxKart engine

2\. Configure the race

Choose the track, number of karts, laps, and AI controller

3\. Start the race and access the states

Initialize the track and world-state readers

4\. Run the game loop

Advance the simulation, read updated states, and repeat

5\. Clean up

Stop the race and release resources

The fourth stage, the game loop, is particularly important. This is where we will eventually connect our own search algorithm.

Remember that the kart is currently driven by SuperTuxKart's built-in AI, not our own algorithm. For now, Python starts the simulation and reads its states.

## 2. Step-by-step explanation of the code

### Step 1 — Import the libraries

```
import timeimport pystk2
```

Here, `pystk2` provides the game engine interface, while `time` allows us to control how quickly the Python loop executes.

### Step 2 — Initialize the graphics

```
graphics = pystk2.GraphicsConfig.sd()graphics.screen_width = 800graphics.screen_height = 600graphics.render = Truegraphics.display = Truepystk2.init(graphics)
```

| Statement                       | Purpose                             |
| ------------------------------- | ----------------------------------- |
| `GraphicsConfig.sd()`           | Select standard-definition graphics |
| `screen_width`, `screen_height` | Set the display resolution          |
| `render = True`                 | Enable graphical rendering          |
| `display = True`                | Show the game on screen             |
| `pystk2.init(graphics)`         | Initialize the game engine          |

The important distinction is that initializing the engine does not start a race. It prepares the game to run.

The official documentation also specifies that `pystk2.init()` should be called only once per Python process.&#x20;

### Step 3 — Configure the race

```
config = pystk2.RaceConfig()config.track = "lighthouse"config.num_kart = 4config.laps = 1
```

This creates the settings for a race with four karts on Lighthouse, completing one lap.

Then:

```
config.players[0].controller = (    pystk2.PlayerConfig.Controller.AI_CONTROL)
```

This line is especially important.

There are two controller modes:

| Mode             | Who drives?                      |
| ---------------- | -------------------------------- |
| `AI_CONTROL`     | SuperTuxKart's built-in AI       |
| `PLAYER_CONTROL` | Commands supplied through Python |

Right now, we use `AI_CONTROL` because we are testing the environment. Later, we will replace it with `PLAYER_CONTROL` and pass actions generated by our own algorithm.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://pystk2.readthedocs.io\&sz=32)

pystk2 0.3.7 documentation



The camera configuration:

```
config.players[0].camera_mode = (    pystk2.PlayerConfig.CameraMode.ON)config.num_cameras = 1
```

ensures that we have a camera following our selected kart.

### Step 4 — Start the race

```
race = pystk2.Race(config)race.start()
```

These two lines have different purposes.

- `Race(config)` creates the race object using our configuration.
- `race.start()` starts the actual race simulation.

Next:

```
world = pystk2.WorldState()track = pystk2.Track()track.update()
```

This gives us access to two different categories of information.

Track

Mainly static information:

Track length, centerline coordinates, widths, and successor connections

WorldState

Dynamic information:

Kart positions, speed, opponents, items, and race time

This distinction will become important in our search algorithm: we can initially construct a graph from the track geometry, then update obstacle information from `WorldState`.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://pystk2.readthedocs.io\&sz=32)

pystk2 0.3.7 documentation



### Step 5 — The most important part: Game loop

```
for step in range(10000):    race_continues = race.step()    world.update()
```

These two functions are the heart of our application.

`race.step()` advances the simulation. Since the kart uses `AI_CONTROL`, its actions are currently selected by the game's built-in AI.

`world.update()` refreshes the Python state object after the game advances.

We can then retrieve the updated information:

```
kart = world.players[0].kartprint(kart.location)print(kart.speed)print(kart.finished_laps)
```

For example, a kart position might look like:

```
[16.81, -13.86, -50.69]
```

These are three-dimensional coordinates \\((x,y,z)\\). In SuperTuxKart, the Y-axis represents vertical height, while X and Z describe the horizontal plane.

The condition:

```
if step % 100 == 0:
```

means we print information every 100 iterations rather than every iteration.

Finally:

```
if not race_continues:    break
```

ends our loop when the race should no longer continue.

### Step 6 — Clean up

```
race.stop()del racepystk2.clean()
```

This stops the race, releases the race object, and cleans up the game engine.

We put these operations inside `finally` because Python executes that block even if an exception occurs within the preceding `try` block.

## 5. Where exactly will our A\* algorithm go?

The most important part to understand is that we do not need to modify the game's internal C++ code.

Our main loop will eventually change from:

```
# Current implementationrunning = race.step()world.update()
```

to something conceptually like:

```
# Future search-based implementationworld.update()state = get_game_state(world)path = search_best_path(state, track)action = generate_action(state, path)running = race.step(action)
```

This future example assumes that we have changed the kart to `PLAYER_CONTROL`. The three helper functions are ones we still need to implement, and our actual planner will likely reuse paths instead of searching again at every step.

The distinction is simple: the game provides observations, our algorithm makes a decision, and the game executes the resulting action.
